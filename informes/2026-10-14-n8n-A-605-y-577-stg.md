## 1. `#605`: el URL Fidelity Guard sin `new URL()`

**Causa, medida en el sandbox real de STG:** un Code node con `typeof URL` devuelve `"undefined"`, y `new URL(...)` lanza `ReferenceError: URL is not defined`.

**Qué pasaba:** `fija()` caía en el `catch` y devolvía siempre `false`. Por eso **todas** las URL de la lista fija se retiraban:
- el enlace del agente;
- `wa.me`;
- la landing.

**Cómo se escapó:** el `#261` se acreditó con una batería en Node local, donde `URL` sí existe.

**Cambio (un nodo):** `fija()` analiza con regex:
- el host acaba en `/`, `?`, `#` o el final de la cadena, así que lo que va antes de una `@` cuenta como usuario y no como host;
- la ruta se toma sin la query, y una `?` sola no cuenta como query.

La lista fija y lo demás del nodo no cambian.

### Aceptación

**Sandbox real de n8n** (`sandbox-605-stg.py`): un workflow temporal con los mismos nombres de nodo que lee el código y el código del vivo como control.

| caso | control (vivo) | cambio |
|---|---|---|
| enlace del agente, con el texto de la exec **87060** | retirado → U4 | **pasa** |
| escalamiento L37 · `wa.me` · landing · landing con `www` y sin barra | retirados → U4 | **pasan** |
| CONTROL: landing con ruta inventada · landing con query · PDF fabricado · dominio raro · `api.whatsapp.com@evil.example` | retirados | **retirados** |
| URL que vino de una tool | pasa | pasa |
| **total** | **6/11** | **11/11** |

En la primera versión el host falso con `@` se colaba; lo endurecí antes del import.

**E2E en el arnés** (copias del vivo, sin envíos), N=3; el control sin el cambio, N=2:
